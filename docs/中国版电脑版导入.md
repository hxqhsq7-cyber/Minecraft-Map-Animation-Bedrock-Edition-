# 中国版电脑版导入与存档替换（v20.6）

此入口仅在 Windows EXE 中显示。适用于普通默认 XOR 密钥的中国版 1.21 世界；中国版电脑版 1.21.120 的 2×1、10 FPS、6 秒循环小样已由用户确认持续播放。其他版本、当前生成的输出和长视频仍需在对应客户端验收。

请将整个便携包完整解压到 F 盘或 D 盘固定目录，再运行 EXE，不要在 ZIP 中直接双击。v20.2.1 在检测到临时解压目录时会在创建 `Data` 前停止启动，避免把持久音轨登记到会被压缩软件清理的位置。

1. 在首页将视频生成 `.mcvideo`。可包含音轨、命名盔甲架和上空提前加载设置。
2. 点击首页的“中国版世界导入（实验性）”，或向下找到第 05 区域。
3. 保存并完全关闭游戏，选择 `.mcvideo`，再选择要添加视频的已有存档或新建存档文件夹，也可直接选择其中的 `level.dat`。旧世界无需搬到新世界。此处选中的路径就是稍后被写回的目标；文件夹窗口只显示文件夹，误选 `db` 时会自动回到对应世界。默认勾选“保留原世界名称”。
4. 设置屏幕原点、朝向和循环。“画面定位”可沿用包内盔甲架、改用固定坐标或自定义盔甲架。需要音轨时选择“加入音轨并部署到普通中国版”；该项默认关闭。选择加入音轨后，默认同时部署本机音轨，包内没有音轨时会明确提示。
5. 默认勾选“生成后自动备份并替换所选目标存档”。不指定 ZIP 时，生成结果保存在方映旁 `Data/Exports`，也可自定义。替换前的原始存档另行完整备份到 `Data/ChinaBackups/<本次标识>-…`，该备份与生成结果是两份不同的数据。软件校验备份后，将结果写回步骤 3 选中的同一个目录，保留启动器已识别的文件夹名。
6. 客户端仍在运行时停止写回，生成 ZIP 和音轨保留，关闭游戏后可点击“替换／重试所选目标存档”。若目标在生成后发生变化，需重新生成，避免覆盖后来保存的进度。写回与音轨部署结果分别显示。成功后从网易发烧游戏启动普通中国版，进入原来的同一个目标存档。仅导出方式需要选择 ZIP，之后自行备份并用完整 ZIP 内容（含 `db`）写回本次所选的同一个存档。
7. 在主世界启用作弊及命令方块，先到达目标区域，等待区块加载，再执行软件结果区的完整播放命令。保留英文双引号及冒号后的名称。完整命令也保存在 ZIP 内的 `方映中国版播放命令.txt`。

重新执行“播放／重新开始”命令可重建并启动控制链。停止命令会清除控制区的命令链和供电方块，保留最后一帧；很大的控制区需要按顺序执行多条清理命令。播放前选空地，画面及命令链会覆盖该位置的方块。

“添加方式”提供两个入口：

- **直接向中国版存档追加**：在完整世界副本中追加独立地图、画面结构及中国版原生命令播放器，再备份写回。
- **一键往返**：软件内解密数据库，调用与国际版入口相同的 `installVideoPackage` 合并核心添加视频，再读取国际版帧顺序，把该播放器转换为中国版原生命令链并加密写回。无需启动国际版游戏、手动转移文件或另装加解密工具；复用合并后的地图 ID，不重复写入地图像素。保留国际版中间播放器文件，新播放请使用结果区生成的中国版完整命令，不能继续使用原 `/function` 指令。

两条流程均以所选旧存档为底稿，保留原区块、玩家记录、原有地图、资源文件、旧播放器及世界设置；必要变更是启用作弊、命令和命令方块，以及不足时提高命令链长度上限。名称默认保留，可取消勾选以改用视频名称。不会把旧世界的数据库拼接到新世界的 `level.dat`，也不更改游戏版本。已有中国版播放器的控制区重叠时拒绝生成，请选择其他空地；普通建筑的占用情况仍需玩家确认，执行播放命令时会放置屏幕与控制链。

中国版的空附加包列表可能写成 `null`。国际版合并阶段仅在副本中把空列表临时视为 `[]`；转换后恢复原启用记录，再按实际音轨设置追加中国版音轨记录，不自动启用中间的国际版行为包。

一键往返当前先实现自动流程，不提供分步导出／回填界面。只支持普通默认密钥的 1.21 世界，不保证中国版专有方块或其他附加包在国际版游戏中可用；本流程离线处理，不在高版本国际版客户端打开世界。已包含同一国际版视频包时会拒绝重复安装，可换一个视频包，或用直接追加方式在其他坐标建立新的播放点。大存档需副本、待写回结果和原始备份的空间；加解密与打包按文件分块处理，结果 ZIP 使用不压缩存储，体积可能大于旧版本输出。

自动替换逐文件解压并核对 ZIP 长度及 CRC，在目标磁盘暂存完整结果；同时对原存档进行完整文件备份，核对它与生成时读取的 SHA-256 指纹。两份数据就绪后才换回所选目标路径，不创建额外的世界目录。写回失败时自动还原原目录；若还原也遇到文件占用等错误，保留旧目录与工作区备份并显示路径，不删除它们。替换前取消不会改变目标内容。重复点击同一次结果时保留替换后保存的游戏进度。程序、配置、音轨、原始备份和生成 ZIP 留在方映所在盘；目标存档继续使用中国版已有位置，该位置可能在 C 盘。替换流程已通过 F 盘隔离测试，更新后的普通客户端流程仍需实测。

结果区可打开“替换前备份”。需要恢复时先完全关闭游戏，确认备份完整，再用它完整替换同一个目标目录的内容；不要只合并复制而留下新数据库文件，也不要把生成 ZIP 当成原始备份。备份占用一份原存档的磁盘空间，保留它直至确认新内容可正常进入和播放。

盔甲架模式会让所有同名盔甲架同步播放，画面按各自水平朝向选择最近的东、南、西、北方向；后加入的同名播放点在下一帧加入。结果区提供新增同名播放点、调整朝向和检查命令。实体须与控制链在同一维度且区块已加载；移动或转向会留下旧画面。合并重复帧造成长停留时，跟随变化在下一个保存帧发生。坐标设置用于控制链附近位置，不会强制把玩家传送离开盔甲架。

中国版“上空提前加载”可沿用包内设置、关闭，或开启并自定义 1–200 帧、上方 8–64 格。默认沿用包内设置，包内未开启则关闭。每排放 5 幅完整画面，再向上堆叠；视频实际保存帧不足时按实际帧数建立。按主世界玩家所处的 16×16 区块固定位置，同区块共用；离开后清理，最多同时保留 4 处。首轮每游戏刻准备 4 幅，准备完成后再自动启动正片和音轨；播放时环形更新后续画面，循环时提前加载下一轮，非循环结束后清理。

该实现使用世界数据库中的画面结构和原生命令方块，不依赖行为包或开发客户端。地图 ID 与正片共用，预加载不重复播放音轨。范围限于屏幕原点周围 64 格，远处盔甲架暂不建立墙。需要保持主控制区、其南侧相邻的辅助控制区及整座预加载墙所在区块加载；不自动添加常加载区域。切换区块后若旧墙区块已卸载，保留清理标记，待整座旧墙重新加载后清理；等待清理的墙仍占用 4 处额度。不要删除标记实体，停止时依次执行结果区所有停止命令。

只在整座墙都为空气、已加载且高度足够时建立，空间不足会跳过，不覆盖建筑。墙可超出 16×16 范围，总高最多 256 格；8×4 屏幕预加载 200 帧需要 40×160×2 格、6400 个展示框，并且有明显的准备等待和额外刷新成本。请勿在墙体范围内建造。地图提前放置已通过原生命令测试，但中国版客户端是否提前完成纹理渲染、能否减少空白仍未验收；大量预加载也可能加重卡顿。

音轨导入保留原始 WAV 音频数据，生成独立音轨资源包并追加世界启用记录。Windows 版将音轨另存到程序旁 `Data/ChinaAudio/<本次标识>_audio`，并在普通客户端的 `games/com.netease/resource_packs` 下建立指向它的目录链接；实际音频文件留在方映数据目录。**普通中国版 1.21.120 的独立提示音已由用户确认可播放，无需开发工作台。**只放入世界 ZIP 的做法曾无声，故不能省略全局部署与客户端重启。每轮第一帧启动一次音频，多个盔甲架附近的听众按玩家标签去重；停止时还需执行结果区“停止音轨”。请先检测音轨，再验收同步；长视频同步与多播放点听感尚未验收。

默认检测 `%APPDATA%/MinecraftPC_Netease_PB`，也可点击“更改普通中国版数据目录”，选择含 `minecraftWorlds` 和 `games/com.netease/resource_packs` 的目录。自动部署失败时，世界 ZIP 仍会保留，结果区明确显示错误，可修正目录后点击“部署／重试本机音轨”。可取消自动部署而仅导出，之后再手动部署。不能将“世界已生成”当作“本机已部署”。

部署新音轨后要退出整个普通中国版客户端进程，再从网易发烧游戏重新启动；只返回主菜单或退出世界不够。游戏启动早于新音轨登记时，不能据“已部署”或聊天里的“已播放声音”断言资源已经加载。若仍无声，先用当前视频专属的音轨检测命令检查，再排查播放距离与同步。

请保留 `Data/ChinaAudio`。移动方映、删除该目录或换电脑后，原链接可能失效，需重新生成并部署；ZIP 本身不会自动为另一台电脑登记全局资源。结果区的“移除本机音轨登记”只移除当前结果对应的目录链接，保留音轨文件和世界；重启客户端后生效。已有同名真实目录或指向其他位置的音轨链接不会被替换。软件不修改游戏安装目录；存档替换只作用于明确选中的目标，原内容在写回前备份。

实际视频反馈：普通中国版 1.21.120 中，132.8 秒视频的音轨移至 F 盘固定目录并完整重启客户端后，用户确认声音检测可听；完整执行带引号及 `:play` 后缀的播放结构命令后，又确认视频重新开始并自动发声。这确认了该次自动启动音轨，不等于整段音画同步、循环重启音轨或其他版本均已验收。

排查过程：仅将音轨放入世界时未发声，原生 `random.orb` 正常。标准资源包启用记录曾漏写 `type: "Addon"`，参照[网易官方联机大厅打包规范](https://github.com/MCNeteaseDevs/netease-bedrock-wiki/blob/main/mcguide/26-%E8%81%94%E6%9C%BA%E5%A4%A7%E5%8E%85/5-%E8%81%94%E6%9C%BA%E5%A4%A7%E5%8E%85%E4%BD%9C%E5%93%81%E4%B8%8E%E5%95%86%E5%93%81%E4%B8%8A%E4%BC%A0%E6%96%87%E6%A1%A3.md)补齐到两份记录，完全重启后仍无声。当时音频和清单完整，但网易启用记录变成 `null`。此失败记录属于补入全局资源路径之前的状态。

官方另提供[开发工作台本地导入与开发测试](https://github.com/MCNeteaseDevs/netease-bedrock-wiki/blob/main/mcguide/12-%E5%85%A5%E9%97%A8%E6%95%99%E7%A8%8B/20-MC%20Studio%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E.md)。通过该入口检测同一音轨包，可以帮助区分资源包内容和普通客户端加载途径的问题；开发包中成功不代表普通客户端也能直接加载。纯地图结构保存在世界数据库中，音轨依赖资源包，两者的加载条件不同。

后续实测：相同音轨包的 5 个文件保持逐字节一致，将工作区改用英文路径后，通过网易开发工作台导入并启动 3.9 开发测试（游戏版本 1.21.120）。独立世界仅启用该组件，网易启用记录保留音轨包 UUID，开发日志也出现该 UUID；用户执行检测命令后确认听到断续提示音。**这确认了该小样在开发客户端可发声，并不代表普通客户端的导入途径已修复，也未验收长音轨、循环同步或多盔甲架音频。**工作台将包部署到开发客户端的全局资源包目录；普通客户端中目前只有测试世界内的副本，缺少同一全局包。这是已观察到的加载差异，尚不能仅据此断定普通客户端补入全局包就能成功。

普通客户端对照实测：将同一修正包另存为独立测试世界，音轨文件和两份启用记录保持不变，仅改世界标题。在普通客户端全局资源目录建立指向 F 盘音轨的链接，完全重启“网易发烧游戏”启动的普通客户端后，用户执行自定义音轨命令，确认听到断续提示音。v20.2 将这个部署步骤加入软件；本次普通客户端听感结果覆盖该小样，不扩大为所有版本、所有音轨或音画同步均通过。

与国际版入口不同，这里不安装方映行为包，也不调用 `.mcfunction`。地图像素和完整画面结构直接写入世界数据库，游戏内置延迟命令链负责推进帧序。工具保留原世界的其他数据与附加包记录，开启音轨导入时只追加本次音轨的资源包记录，重新加密后输出世界 ZIP，无需额外安装加解密 EXE。

控制链按区块边界对齐，最大占用 16×16 的水平范围，实际高度随帧数增长，最高 256 格。软件会检查屏幕、链条和世界高度；长视频需要较低的 Y，且播放时屏幕和控制链均须处于已加载区块。此方式没有验证玩家离开后继续播放，不自动申请常加载区域。

单区块控制链最多包含 16,384 条播放命令。固定坐标一般每帧 1 条，盔甲架每帧 4 条；预加载另加每帧 2 条进度命令，音轨还需少量启动命令。不开预加载时盔甲架通常最多 4096 个保存帧，加入音轨后略减。开启预加载还需满足辅助命令链容量，超限时拒绝生成并提示缩短视频或降低帧率。资源中心二次加密和自定义密钥仍不支持。中国版输出也未接入现有旧世界升级或世界反导出 MP4 流程；需要 MP4 时可直接读取原 `.mcvideo`。

地图复用可以减少独立地图数据，播放器仍加载完整帧。95 秒、8×4、20 FPS 的丰富画面可能产生大量地图；命令链时序通过不等于客户端纹理加载、流畅度或长视频空白问题全部解决。

加解密格式参考 [HTMonkeyG 的开源工具](https://github.com/HTMonkeyG/XOR-MC-Archive-Decrypt)：普通数据库文件的魔数为 `80 1D 30 01`，正文使用默认密钥 `88329851` 进行周期 XOR。实现只在已复制的普通世界数据库上操作，不处理附加包或资源中心加密文件。原工具也明确列出不支持的二次加密格式。数据库结构保存和加载基于 [Minecraft 官方 structure 命令](https://learn.microsoft.com/en-us/minecraft/creator/commands/commands/structure)。
