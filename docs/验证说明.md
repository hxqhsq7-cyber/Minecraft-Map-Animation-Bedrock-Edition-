# v18 验证说明

Windows 与 Android 共用转换、播放器、世界合并和区块预加载核心。构建工具继续使用固定版本官方 Electron、rcedit、JDK 和 Android SDK，工具、缓存和产物位于 F 盘工作区。

- 原播放器检查覆盖 1–16,384 帧、可变帧时长、循环、非循环末帧保留、四方向和周期完整刷新。
- 原旧世界检查覆盖地图、时序、数据库和音轨保留，缺帧拒绝、取消及重复升级；多盔甲架检查覆盖独立朝向、角度边界和音频去重。
- 预加载逻辑检查覆盖 16×16 区块、负坐标、区块内不搬迁、多人共用、跨区块清理、环形复用、循环回绕、非循环结束、二次播放、建筑占用拒绝、卸载区块清理持久化和关闭后的重复升级。
- 合成视频覆盖 v6 视频包、有无地图复用、固定／盔甲架定位、安装、修复、优化及无视频包世界升级；预加载结构为完整帧，复用原地图 ID。
- 打包 EXE 检查覆盖 H.264/AAC、PCM 音频、内存、磁盘、文件夹输出及真实表单自定义预加载和无原视频包升级。
- Windows ZIP 检查 CRC、全部构建清单 SHA-256、源码与包内 HTML 一致性；APK 检查对齐、CRC、资源一致性、v1/v2/v3 签名和原证书一致性。

官方 BDS 1.26.30.5 中执行了 9 项实际引擎断言：命令方块事件来源、三面完整墙放置、多人共用、跨区块清理、停止清理、无地图物品掉落、二次播放、结束清理、清理后持久记录删除。使用实际结构和方块 API、模拟观看者，没有连接客户端。

引擎实测发现，在函数内部发送脚本事件会丢失命令方块来源。开启预加载后的时钟改为直接发送事件，由脚本按实际命令方块坐标驱动原播放函数。未开启过的输出保留原时钟和依赖。

可复现检查为 tests/prefetch.cjs、tests/prefetch-engine.py、tests/browser-smoke.js，结果保存在 logs/。原修复版本也已用官方引擎验证函数加载、等待计数及非循环样例的两次按钮启动。

这些检查不证明客户端会绘制头顶地图，也不证明长视频空白或卡顿已消除。尚需 Windows 客户端和真实安卓设备验收长视频画面、流畅度及音画同步。未执行手机覆盖安装，未完成 95 秒、8×4、20 FPS 视频的视觉验收。

个人世界、原视频、日志和私钥不随仓库发布。小型合成夹具位于 tests/fixtures/，测试输出被 Git 忽略。

## v18 MP4 导出

- tests/reverse.cjs 验证视频包／世界只读读取、地图拼接上下左右、增量帧、连续重复帧、复用、最新序列优先、删除记录、活动表过滤、四种数据库压缩、损坏与缺图拒绝及取消。
- tests/reverse-engine.py 用官方 BDS 1.26.30.5 整理合成世界，产生实际 SST 表；再通过真实 EXE 表单恢复 MP4。
- tests/reverse-smoke.cjs 验证视频包、原始日志世界、合成 SST 和官方引擎整理世界的 H.264/AAC、离线 AAC 备用编码、直接保存、内存下载、无声输出与取消恢复。
- tests/verify-reverse.py 用独立 FFprobe／FFmpeg 完整解码，检查帧数、分辨率、帧率、色块拼接和重复帧停留时间，确认音轨可解码且非静音。
- 本机完整旧世界只读恢复了 1024×512、20 FPS、1917 帧、视频轨 95.85 秒，输出约 23.9 MB；独立探测和完整音视频解码通过。该世界与视频未上传。

AAC 以 1024 采样帧编码，容器／音轨时长可能含少量头尾填充。长样例的视频轨为 95.85 秒，FFprobe 显示容器时长约 95.915 秒；这不等同于视频帧被延长。未做听感验收，也未在 Android 真机上安装或编码。
