# 方映 MapCinema

**让地图，动起来。**

方映是一款面向 Minecraft 基岩版的本地视频转换工具。它将视频拆分为地图画帧，生成地图数据、展示框结构和播放函数，再通过游戏内的播放时钟依次加载，让普通地图墙成为可以播放视频的屏幕。

支持把视频加入已有世界，也支持用同名盔甲架设置多个同步播放点。视频转换在本机完成，无需上传素材。本目录对应 Windows 桌面版 v16.1。

## 工作原理

```mermaid
flowchart LR
    A[本地视频] --> B[按目标帧率抽帧]
    B --> C[切分为 128 × 128 像素地图块]
    C --> D[生成地图数据与展示框结构]
    D --> E[打包或合并进世界]
    E --> F[播放时钟按游戏刻加载画面]
```

1. **把画面变成地图。** 根据屏幕尺寸缩放或裁剪视频帧，将每帧拆成多张地图。地图像素与编号写入基岩版世界数据库，展示框引用对应地图编号。
2. **把每帧变成结构。** 将地图墙保存为 `.mcstructure`，播放时使用 `structure load` 更新画面。固定坐标模式可只更新发生变化的地图块；命名盔甲架模式加载完整画面，以适应不同播放点的位置和方向。
3. **用时钟推进播放。** 一个重复命令方块驱动记分板，记录当前帧、等待时间和播放状态；分层函数定位需要加载的帧，避免为长视频铺设随帧数增长的命令方块链。
4. **减少重复数据。** 完全相同的地图块可跨画面复用地图编号，连续重复帧可合并并延长停留时间。固定坐标模式在后续画面变化时周期性补写完整帧，帮助恢复缺失区域；这种刷新不能消除客户端的资源限制。
5. **单独播放音轨。** 可选音轨通过配套资源包加入世界，由播放函数启动。声音按实际时间播放，画面按游戏刻推进，因此游戏卡顿时仍可能出现音画偏移。

## 功能

- 自定义地图墙尺寸，横纵各 1–16 张地图，每张地图为 128 × 128 像素。
- 提供 5、10、20 FPS 目标帧率，以及截取片段、补黑边、居中裁剪和循环播放设置。
- 支持固定坐标播放，以及同名盔甲架的多播放点同步显示。
- 屏幕按各盔甲架的水平朝向选择最近的东、南、西、北方向。
- 支持地图复用、连续重复帧合并，以及可选的轻微画面变化抑制。
- 导出可复用视频包、可导入世界文件或世界文件夹。
- 将视频合并进已有世界，并输出世界副本。
- 没有原视频包时，可升级保留完整方映播放器数据的旧世界。
- Windows 版提供直接写入磁盘的转换方式和便携式 EXE。

## 快速使用

1. 完整解压 Windows 便携包，运行 `方映.exe`，保留 EXE 旁的运行文件。
2. 选择视频，设置屏幕大小、目标帧率、截取范围和定位方式，需要时添加音轨。
3. 直接导出世界，或先生成视频包，再通过“已有世界：合并／升级”加入自己的世界。
4. 导入生成的 `.mcworld`，进入允许作弊的世界，在空地使用软件提供的放置、播放和停止命令。

播放命令会放置或清理控制区方块，请避开建筑，并保留原世界备份。使用软件生成的完整命令，其中包含本次视频的命名空间和坐标。

### 导出格式

| 格式 | 用途 |
| --- | --- |
| `.mcvideo` | 方映视频包，在软件中合并进世界，不能直接作为 Minecraft 世界导入。 |
| `.mcworld` | 打包好的基岩版世界，可交给 Minecraft 导入。 |
| 世界文件夹 | 适合电脑端管理和保存较大的世界输出。 |

### 同名盔甲架播放

选择“命名盔甲架”并填写名称后，与控制器同维度、处于已加载区块中的所有同名盔甲架，共享同一视频进度。软件提供新增同名盔甲架和调整朝向的可复制命令。

画面在下一播放帧更新位置与方向；连续重复帧合并形成长时间停留时，不持续追踪实体。当前只支持四个水平方向，移动或转向后会留下旧位置的地图墙，不会自动清除周围方块。

### 按钮重播

非循环视频播完后，需要再次执行软件提供的“播放”命令，才能重置进度。单纯重新给原来的紫色播放时钟通红石不会复位。

若需要按钮控制，另放一个命令方块，设置为 **脉冲／无条件／需要红石**，填入软件提供的完整播放命令，再连接按钮。将这个启动方块放在播放器清理范围之外，保留原播放时钟。

### 没有视频包的旧世界升级

打开“已有世界：合并／升级”，选择“仅用旧世界升级（无需视频包）”，然后选择 `.mcworld` 并生成升级副本。

此入口需要世界中保留一个完整的方映播放器及元数据。它不是从任意地图墙恢复视频的工具；数据缺失或存在多个播放器时，当前版本无法自动升级。仅替换电脑软件不会更新已经导入游戏的世界。

## 性能与兼容性

- 目标帧率不等于实际播放帧率。视频长度、独立地图数量、屏幕尺寸、播放点数量、磁盘速度和客户端资源限制都会影响效果。
- 播放时间线由游戏刻驱动；20 FPS 目标设置需要游戏保持相应的刻速度。
- 多个屏幕可共用地图数据，但每个屏幕仍有结构和展示框更新开销。同名播放点需保持区块加载。
- 控制器尝试创建常加载区域；创建失败时需要检查世界的常加载区域数量。迁移控制组前，应先在旧坐标执行清理控制命令。
- 地图复用对静止区域和重复画面更有效，持续变化的视频仍可能生成大量地图。轻微变化抑制可能让字幕或小物体暂时停留，文字类内容建议使用无损模式。
- 音轨在开播时向屏幕附近的玩家启动，中途加入者可能需要等待下一轮或重新播放。
- 当前 Windows EXE 未配置 Authenticode 发布签名。

## 验证范围

v16.1 已通过打包 EXE 的实际转换与旧世界升级流程检查，以及导出 ZIP、地图引用、帧时序和音轨数据核验。

已使用官方 Bedrock Dedicated Server **1.26.30.5** 验证修复后函数的加载、播放时钟计数和首帧推进；也在已加载区块内，用非循环短视频样例验证了脉冲命令方块连续两次启动并播放至结束。

这些检查不代表所有基岩版版本和设备都已兼容，也不替代 Minecraft 客户端中的整段视频画面、流畅度与音画同步验收。

## 源码入口

- `app/MapCinema.html`：转换界面、地图与结构生成、世界合并和播放函数生成。
- `app/main.cjs`：Windows 桌面运行入口。
- `tests/`：转换、播放时序、旧世界升级及多盔甲架相关检查。
- `tools/build.py`：Windows 打包脚本。
- `tools/toolchain-lock.json`：官方构建工具的固定版本、下载地址与 SHA-256。

## 从源码构建 Windows 版

需要 Windows x64 和 Python 3.11 或更新版本。在仓库目录执行：

```powershell
.\build.ps1
```

首次构建会从 Electron 官方 GitHub Release 和 npm 官方注册表下载固定版本工具，校验 SHA-256 后保存到仓库的 `.toolchain` 目录。缓存与临时文件都位于项目目录，无需全局安装 Electron 或 Node.js。构建产物位于 `release/`，目录不可写时请将项目移到有写入权限的位置。

运行开发检查还需要 Node.js 24 或更新版本：

```powershell
node tests/playback.cjs
node tests/world-only.cjs
node tests/multi-anchor.cjs
node tests/smoke.cjs
python tests/verify.py
```

`smoke.cjs` 在构建后运行打包的 EXE，并使用独立测试配置与合成素材验证导出。`tests/fixtures/reference-*.html` 是兼容性回归使用的旧版参考实现，不是桌面软件入口。
